# Commit 23: Streaming Excel Export Memory Profile (500,000 Rows under 512 MiB RAM)

Container Memory Limit (Kernel cgroup v2 verified on api-1):
  docker-compose.yml: deploy.resources.limits.memory = 512M
  /sys/fs/cgroup/memory.max = 536870912 bytes (512.0 MiB)

Implementation Architecture:
  - PostgreSQL Server-Side Named Cursor (`report_details_server_cursor`, `itersize=batch_size`, default 1000)
  - Disk-backed `tempfile.mkstemp(suffix=".xlsx")` + `xlsxwriter.Workbook(tmp_path, {"constant_memory": True, "strings_to_urls": False})` (never `BytesIO` or `in_memory=True`)
  - SQL aggregation (`COUNT`, `SUM`, `GROUP BY event_id, zone_code`) for `Summary` worksheet
  - Timezone conversion to `Asia/Taipei` (+ header timezone notation) and numeric `write_number(..., "#,##0.00")` for all monetary columns
  - 64KB chunked `StreamingResponse` with `X-Report-Rows` header and `finally: os.remove(tmp_path)` cleanup

Verification Summary:
  - Kernel cgroup limit verified: `/sys/fs/cgroup/memory.max = 536870912` bytes (exact 512.0 MiB).
  - Independent 500,000-row verification: HTTP `X-Report-Rows: 500000` AND streaming XML `<row ` tag count on downloaded `xl/worksheets/sheet2.xml` = `500000` data rows (excluding header row).
  - Container non-reclaimable process RAM (`cgroup memory.stat anon`, including both uvicorn server + benchmark client inside `api-1`): peaked at `95.68 MiB` (+10.56 MiB over `85.12 MiB` baseline, << `512.0 MiB` limit) with `oom_kill = 0`.
  - Earlier `memory.peak = 537022464` (512.14 MiB) included reclaimable Linux filesystem page cache (`memory.stat file`) temporarily buffered during disk writes and synchronously reclaimed by the kernel before OOM.
